# CutCraft

Помощник подготовки коротких эдитов из готового видео. По заданию и каталогу фрагментов система составляет монтажный план с таймкодами, подписями и ссылками на источник. Целевая цепочка: выбор → проверка → одно исправление → повторная проверка → раскадровка.

## Установка

Требуется Python 3.10+. Текущая реализация использует стандартную библиотеку; устанавливать пакеты не нужно.

```bash
git clone git@github.com:cemouse/cutcraft.git
cd cutcraft
git switch codex/connect-planner
```

Подключение монтажёра находится в ветке `codex/connect-planner` и [PR #1](https://github.com/cemouse/cutcraft/pull/1). До его слияния эта инструкция относится к указанной ветке.

## Демонстрация без API

```bash
python3 main.py --demo
```

Открыть напечатанный путь `output/.../report.html`. Демонстрация использует фиксированные ответы, специально внесённую ошибку и условные SVG-карточки. Она показывает управление этапами и историю изменений, но не работу реальных моделей.

## Настройка OpenRouter

```bash
cp .env.example .env
```

Заполнить `OPENROUTER_API_KEY` в локальном `.env`. Остальные параметры:

| Переменная | Назначение |
|---|---|
| `OPENROUTER_BASE_URL` | Официальный API: `https://openrouter.ai/api/v1` |
| `TEXT_MODEL_NAME` | Текстовая модель; проверена `dots-studio/dots-3-note-preview:free` |
| `VISION_MODEL_NAME` | Модель проверяющего; адаптер изображений ещё не подключён |
| `OPENROUTER_FREE_ONLY` | `true`; клиент допускает только бесплатные ID с подтверждённой нулевой ценой |
| `MODEL_TIMEOUT_SECONDS` | Таймаут одного HTTP-запроса, по умолчанию 60 секунд |

`.env` загружается автоматически; переменные окружения процесса имеют приоритет. Ключи не включаются в Git. Клиент не использует платный fallback или автоматические повторы. Доступность бесплатных моделей зависит от провайдера; при HTTP 429 запуск останавливается с сообщением об ограничении.

## Запуск монтажёра

Создание плана:

```bash
python3 planner_cli.py --task "Объясни результат и ограничения"
```

Исправление по замечаниям, соответствующим выбранному плану:

```bash
python3 planner_cli.py --task "Объясни результат и ограничения"   --plan output/your-plan.json --review path/to/review.json
```

Результат сохраняется в JSON и ещё не считается принятым критиком. Каждая команда выводит путь созданного файла.

Проверка создания и доработки контрольного дефекта — два реальных API-запроса:

```bash
python3 scripts/check_planner_live.py
```

В этой проверке используются учебный каталог и заранее подготовленное замечание. [Сохранённые результаты](docs/evidence/planner/README.md) подтверждают работу монтажёра, а не всего мультимодального цикла.

## Архитектура

| Модуль | Назначение |
|---|---|
| `planner.py` | Создание плана и исправление замечаний |
| `reviewer.py` | Интерфейс проверяющего; сейчас реализован демонстрационный режим |
| `model_client.py` | Клиент OpenRouter, настройки и контроль бесплатных моделей |
| `contracts.py`, `schemas/` | Проверки формы, ссылок, таймкодов, цитат и правил доработки |
| `main.py` | Порядок этапов, один раунд исправления, состояния и сохранение |
| `render.py` | Статическая HTML-раскадровка |

Python и файлы работают локально, модели вызываются через API. Запуск Claude Code/Codex CLI внутри приложения, отдельная VM и база данных не требуются.

## Данные и результаты

Каталог содержит исходную длительность, признак настоящих материалов и сегменты с `segment_id`, `start`, `end`, `transcript`, `frame_paths`. Пути кадров относительны файлу каталога. План содержит ровно три сцены общей длительностью 20–30 секунд.

При доработке сохраняются `scene_id` и принятые сцены. Полностью принятый план не вызывает дополнительный запрос, `needs_human_review` прекращает автоматическую доработку. Детали — в [контрактах](docs/CONTRACTS.md).

Оркестратор сохраняет версии плана и замечаний, `history.json`, `status.json` и `report.html` в отдельной папке `output/`. Статусы: `demo_accepted`, `accepted`, `needs_human_review`, `failed`.

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

На 15 октября проходят 22 локальных теста. Реальный монтажёр создал план и исправил контрольную подпись, сохранив две принятые сцены. Полный запуск без `--demo` ожидает подключения реального проверяющего. Приёмка на настоящем видео ещё не подтверждена.

## Ограничения

Предобработка видео выполняется заранее. Экспорт MP4, музыка, озвучка и публикация не входят в текущую реализацию. По стоп-кадрам нельзя полностью оценить движение и звук; верность источнику не является независимым фактчекингом.

Секреты, `.env`, `output/`, виртуальное окружение и настройки IDE исключены из Git. Исходные материалы должны быть разрешены к передаче выбранному API-провайдеру.
