# CutCraft

CutCraft делает план короткого ролика из длинного видео. Вы пишете, о чём должен быть ролик. Монтажёр (LLM) выбирает три фрагмента и пишет к ним заголовки, проверяющий (LLM с изображениями) сверяет их с транскриптом и кадрами. Если он находит ошибку, монтажёр исправляет одну эту сцену. На выходе — раскадровка с историей исправлений; по ней можно собрать вертикальное видео.

## Установка

Нужен Python 3.10+. Основной код использует только стандартную библиотеку.

```bash
git clone https://github.com/cemouse/cutcraft.git
cd cutcraft
```

## Демо без ключа

```bash
python3 main.py --demo
```

Откройте напечатанный путь к `output/.../report.html`, сервер не нужен. Демо берёт первые три фрагмента реального каталога, но ответы ролей в нём фиксированные, а ошибка в подписи внесена специально. Оно показывает, как устроен цикл, а не как работают модели.

## Настройка OpenRouter

```bash
cp .env.example .env
```

Впишите ключ в `OPENROUTER_API_KEY` в локальном `.env`. Остальное уже заполнено:

| Переменная | Значение |
|---|---|
| `TEXT_MODEL_NAME` | модель монтажёра, в шаблоне `nvidia/nemotron-3.5-super-vl:free` |
| `VISION_MODEL_NAME` | модель проверяющего, должна принимать изображения; в шаблоне та же. Другие кандидаты: `python3 scripts/list_free_vision_models.py` |
| `OPENROUTER_FREE_ONLY` | `true`: клиент пускает только ID с `:free` и нулевой ценой |
| `MODEL_TIMEOUT_SECONDS` | лимит на один запрос, 1–120 с, в шаблоне 120 |
| `OPENROUTER_BASE_URL` | `https://openrouter.ai/api/v1` |

`.env` загружается сам, переменные окружения важнее. Ключ в Git не попадает. Платного запасного варианта и автоматических повторов нет: при ошибке 429 запуск останавливается и пишет причину.

У бесплатного тарифа дневная квота на аккаунт, а полный прогон тратит 2–4 запроса. Поэтому отлаживайтесь на `--demo`. Бесплатные модели бывают недоступны: 15 октября модели Gemma 4 весь вечер отвечали 429, а `dots-3-note-preview` иногда тратила весь лимит на рассуждения и не отвечала.

## Полный запуск

```bash
python3 main.py --catalog data/catalog.json --task "Объясни за 30 секунд, почему учёные уверены, что был Большой взрыв"
```

Без замечаний цикл делает 2 запроса, с исправлением 4. На реальном видео он занимает 20–40 секунд. Результат лежит в `output/<время>/`.

Задание подбирайте под содержание видео. В этом интервью нет разговора об ограничениях метода, и с заданием «объясни результат и ограничения» монтажёр притягивал случайный фрагмент.

## Превью видео

По итоговому плану любого запуска можно собрать вертикальное видео: заголовок сцены сверху, дословные субтитры снизу.

```bash
pip install pillow
python3 scripts/render_short.py --video shtern_big_bang.mp4
```

Нужны ffmpeg и исходное видео: в Git его нет, ссылка в [data/SOURCE.md](data/SOURCE.md). Скрипт берёт последний запуск из `output/` и сохраняет `short.mp4` рядом с отчётом. Модели в нём не участвуют, это превью будущего экспорта.

## Отдельные роли

Монтажёр без проверяющего:

```bash
python3 planner_cli.py --task "Объясни за 30 секунд, почему учёные уверены, что был Большой взрыв"
python3 scripts/check_planner_live.py
```

Проверяющий на трёх контрольных случаях (корректный план, потерянная оговорка, посторонний кадр):

```bash
python3 scripts/check_reviewer_live.py
```

Эти проверки тратят живые запросы. Подробности в [результатах монтажёра](docs/evidence/planner/README.md) и [проверяющего](docs/evidence/reviewer/README.md).

## Как устроено

```text
main.py
  → build_plan(task, catalog)                  монтажёр
  → validate_plan                              код
  → review_plan(task, catalog, plan, frames)   проверяющий, видит кадры
  → revise_plan(...) при замечаниях            монтажёр
  → validate_revision, повторная проверка      код и проверяющий
  → history.json, status.json, report.html     код
```

| Модуль | Что делает |
|---|---|
| `planner.py` | создаёт план и исправляет его по замечаниям |
| `reviewer.py` | проверяет сцены по транскрипту и кадрам; аргументов монтажёра не видит |
| `model_client.py` | ходит в OpenRouter: настройки, бесплатные модели, картинки, лимит времени, разбор JSON |
| `contracts.py`, `schemas/` | проверяют форму, ссылки, таймкоды, цитаты и правила доработки |
| `main.py` | порядок шагов, один раунд исправления, статусы, сохранение |
| `render.py` | HTML-раскадровка |
| `scripts/render_short.py` | видео по готовому плану |

Оркестратор — обычный код: порядок шагов и лимиты известны заранее. Если после повторной проверки замечания остались, результат получает статус `needs_human_review` и решение остаётся за человеком.

Всё работает локально, модели вызываются по API. VM, база данных и запуск Claude Code или Codex внутри приложения не нужны.

## Данные и результаты

Каталог описывает фрагменты одного видео: `segment_id`, `start`, `end`, `transcript`, `frame_paths`. План — ровно три сцены на 20–30 секунд, у каждой заголовок и дословная цитата. Проверка — одно решение на сцену. Подробности в [контрактах](docs/CONTRACTS.md).

Каждый запуск пишет в свою папку `output/`: `input.json`, `plan_0.json`, `review_0.json`, при исправлении `plan_1.json` и `review_1.json`, затем `history.json`, `status.json`, `report.html`. Статусы: `demo_accepted`, `accepted`, `needs_human_review`, `failed`.

## Ограничения

Транскрипт и нарезка готовятся заранее. Проверяющий видит стоп-кадры и не слышит звук. Сейчас обе роли работают на одной модели, поэтому проверка не полностью независима. Ответы моделей меняются от запуска к запуску; сохранённые прогоны — примеры, а не оценка надёжности. Верность источнику не означает проверку фактов.

Ключи, `.env`, `output/`, виртуальные окружения и настройки IDE в Git не попадают. Исходное видео в репозиторий не кладём. Java-шаблон IDEA к Python-MVP не относится.
