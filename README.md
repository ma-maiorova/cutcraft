# CutCraft — командный MVP

Помощник подготовки короткого эдита: готовый каталог одного видео → три сцены на 20–30 секунд → проверка → одно исправление → повторная проверка → HTML-раскадровка.

## Запуск сейчас: демонстрация без ключей

Python 3.10+, только стандартная библиотека. Из корня репозитория:

```bash
python3 main.py --demo
python3 -m unittest discover -s tests -v
```

Открыть напечатанный `output/.../report.html`. Файл самодостаточный, сервер не нужен. Результаты каждого запуска — в отдельной папке.

**Деморежим использует фиксированные ответы и условные SVG-карточки.** Реальный монтажёр уже подключён к OpenRouter через `model_client.py`. Реальный проверяющий ещё не подключён: полный `main.py` без `--demo` пока остановится на нём. Реальные материалы готовит Артём.

## Как будет работать запуск настоящих агентов

Один локальный процесс Python вызывает две логические роли через API моделей. Агент монтажёра — `planner.py` + инструкция + контекст + модель. Проверяющий — `reviewer.py` + отдельная инструкция/контекст + модель с поддержкой изображений. Код `main.py` управляет очередностью и лимитами; отдельный LLM-оркестратор и два сервера не нужны.

```text
main.py
  → build_plan(task, catalog)              [Марина: API модели]
  → проверки формата/таймкодов             [Кирилл: код]
  → review_plan(task, catalog, plan, frames) [Галим: API модели + картинки]
  → revise_plan(...) при замечаниях        [Марина: API модели]
  → повторная проверка                    [Галим]
  → JSON-история и report.html             [Кирилл]
```

Без замечаний — два основных вызова модели; с одной доработкой — четыре. Дополнительные технические повторы считаются отдельно. После повторной проверки оставшиеся замечания передаются человеку.

**Решение команды на 15 октября: OpenRouter, только бесплатные модели.** Приложение запускаем локально. Для обеих ролей используем точные ID бесплатных вариантов (`:free`); для критика обязательно image input. Для текстового монтажёра проверена `dots-studio/dots-3-note-preview:free`; модель критика и реальная передача изображений ещё требуют проверки. Никаких автоматических переключений на платные модели.

На бесплатном плане заявлено 50 запросов в день; квота общая для аккаунта, смена ключей не создаёт новый лимит. Один прогон требует 2–4 основных запроса, поэтому экономим квоту и отлаживаем формат через `--demo`. При 429 сохраняем ошибку/результаты и останавливаемся либо выполняем ограниченный повтор; не переходим на платный маршрут. Проверить лимиты аккаунта перед репетицией.

Настройки — в [.env.example](.env.example). Получить API-ключ в OpenRouter и сохранить только локально. Пустые имена моделей в шаблоне намеренны: сначала выбрать доступные бесплатные модели, подтвердить нулевую цену и image input у критика. Не использовать платный ID без суффикса вместо бесплатного. Доступность бесплатного варианта не гарантирована.

**Что уже есть в каркасе:** каталоги/примеры, инструкции ролям, проверки контрактов и таймкодов, один цикл доработки, история JSON и HTML. **Что уже подключено дополнительно:** общий текстовый HTTP-клиент OpenRouter, загрузка локального `.env`, проверка бесплатного ID/нулевой цены и реальные вызовы монтажёра. **Что осталось:** мультимодальный адаптер проверяющего и реальные материалы. Бесплатные модели могут отвечать 429; клиент не переключается на платную модель и не расходует квоту бесконечными повторами.

Источники: [тарифы](https://openrouter.ai/pricing/), [бесплатные маршруты](https://openrouter.ai/docs/guides/routing/routers/free-router).

Claude Code / Codex могут помогать участникам писать код. Запускать их CLI как часть приложения для этого MVP не планируем. Приложение обращается к моделям через API, а не к текущим чатам разработчиков. Локальное приложение не означает локально установленную LLM.

Официальные инструкции: [OpenRouter Quickstart](https://openrouter.ai/docs/quickstart), [API chat completions](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request).

## Перед первым реальным запуском

1. Кирилл, Марина и Галим выбирают точные ID бесплатных моделей OpenRouter и тестируют текстовый запрос и реальную картинку с машины демонстрации.
2. Кирилл проверяет готовый `model_client.py`: он загружает `.env` без переопределения переменных shell, проверяет модель по актуальному каталогу и ограничивает длительность HTTP-запросов. Клиент пока без автоматических повторов. Для Галима требуется расширить его на мультимодальные сообщения.
3. Марина проверяет уже подключённые `build_plan` и `revise_plan`, Галим подключает API в `review_plan`. Критик получает реальные байты PNG/JPEG, а не только путь в тексте.
4. Артём заменяет данные реальными и проверяет таймкоды. `assets_are_real: true` только после замены условных материалов.
5. Пройти тесты и затем запустить:

```bash
python3 main.py --catalog data/catalog.json --task "Объясни результат и его ограничения"
```

Эта команда станет рабочим live-режимом ПОСЛЕ подключения моделей. До этого предусмотрен только `--demo`.

Имена конфигурации зафиксированы в `.env.example`: `OPENROUTER_API_KEY`, `OPENROUTER_BASE_URL`, `TEXT_MODEL_NAME`, `VISION_MODEL_NAME`, `OPENROUTER_FREE_ONLY`, `MODEL_TIMEOUT_SECONDS`. Их чтение реализовано в `model_client.py`; допускаются только официальный endpoint и бесплатные модели с подтверждённой нулевой ценой. `VISION_MODEL_NAME` необходимо выбрать перед подключением критика.

## Отдельный запуск монтажёра (модуль Марины)

В локальном `.env` заполнить `OPENROUTER_API_KEY` и `TEXT_MODEL_NAME` точным доступным ID `:free`. Автоматическая загрузка `.env` реализована, SDK не нужен. Ключи не коммитить.

```bash
python3 planner_cli.py --task "Объясни результат и ограничения"
```

Команда делает настоящий запрос API и сохраняет план JSON в `output/`, но не помечает его проверенным критиком. При 429 план не создаётся, платного fallback нет. Повторять позже или явно выбрать другую доступную бесплатную модель.

Доработка по подготовленным замечаниям (они должны соответствовать текущему плану):

```bash
python3 planner_cli.py --task "Объясни результат и ограничения" --plan output/your-plan.json --review path/to/review.json
```

Обе команды без `--demo` используют настоящую модель; `--demo` доступен для разработки без квоты. При доработке валидируются scene_id и неизменность принятых сцен.

## Общие данные и интерфейсы

[Контракт 1.0](docs/CONTRACTS.md), примеры: [каталог](examples/catalog.json), [план](examples/plan.json), [замечания](examples/review.json). Точные проверки — `contracts.py`.

- Каталог: `schema_version`, `source_duration`, `assets_are_real`, `segments`.
- Сегмент: `segment_id`, `start`, `end`, `transcript`, `frame_paths`.
- План: `schema_version`, ровно три `scenes` с суммарной длительностью 20–30 секунд.
- Проверка: `schema_version`, `items` — решение по каждой сцене.
- Пути кадров относительны файлу каталога, картинки внутри той же папки данных.

Каждый разрабатывает свой блок на примерах, не ожидая остальных. Для полноценного демо соединяем реальные данные и API. Не менять одновременно чужие модули без согласования; общие изменения контракта проводит Кирилл вместе с владельцами.

## Что сохраняется

`input.json`, `plan_0.json`, `review_0.json`, при исправлении `plan_1.json`/`review_1.json`, `history.json`, `status.json`, `report.html`. Статусы: `demo_accepted` / `accepted` / `needs_human_review` / `failed`.

## Границы MVP

Подготовка исходного видео выполняется заранее. Без экспорта MP4, TTS, музыки, сложного монтажа, автопубликации и обязательной VM. Проверяем верность пересказа источнику; стоп-кадры не подтверждают качество звука и движения.

## Безопасность и работа с репозиторием

Секреты — только в локальном окружении или игнорируемом `.env`. Не отправлять ключи в чат/репозиторий. Данные для API должны быть разрешены к передаче выбранному провайдеру. Пользовательские исходные видео не добавлять в Git без согласования; для демо достаточно разрешённых кадров/транскрипта.

`output/`, `.env`, `.idea/`, виртуальное окружение и кэш исключены. Существующий Java-шаблон в локальной IDEA не относится к Python-MVP. Структура инструкций не переносит код и не меняет запуск.
