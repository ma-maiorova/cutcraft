# CutCraft

Помощник подготовки коротких эдитов из готового видео. По заданию и каталогу фрагментов система составляет монтажный план с таймкодами, подписями и ссылками на источник. Целевая цепочка: выбор → проверка → одно исправление → повторная проверка → раскадровка.

## Установка

Требуется Python 3.10+. Текущая реализация использует только стандартную библиотеку, устанавливать пакеты не нужно.

```bash
git clone https://github.com/cemouse/cutcraft.git
cd cutcraft
```

## Демонстрация без API

```bash
python3 main.py --demo
```

Открыть напечатанный путь `output/.../report.html`: файл самодостаточный, сервер не нужен. Демонстрация берёт первые три сегмента реального каталога, но ответы ролей фиксированные, а ошибка в подписи внесена специально. Она показывает управление этапами и историю изменений, а не работу моделей.

## Настройка OpenRouter

```bash
cp .env.example .env
```

Заполнить `OPENROUTER_API_KEY` в локальном `.env`. Остальные параметры:

| Переменная | Назначение |
|---|---|
| `OPENROUTER_BASE_URL` | Официальный API: `https://openrouter.ai/api/v1` |
| `TEXT_MODEL_NAME` | Модель монтажёра; проверена `dots-studio/dots-3-note-preview:free` |
| `VISION_MODEL_NAME` | Модель проверяющего с image input; ещё не выбрана |
| `OPENROUTER_FREE_ONLY` | `true`; клиент допускает только ID `:free` с подтверждённой нулевой ценой |
| `MODEL_TIMEOUT_SECONDS` | Таймаут одного HTTP-запроса, от 1 до 120 секунд, по умолчанию 60 |

`.env` загружается автоматически; переменные окружения процесса имеют приоритет. Ключи в Git не попадают. Клиент не использует платный fallback и автоматические повторы: при HTTP 429 запуск останавливается с сообщением об ограничении.

На бесплатном плане действует дневная квота запросов на аккаунт. Один полный прогон требует 2–4 запроса, поэтому формат отлаживаем через `--demo`, а живые запросы бережём. Доступность бесплатных моделей не гарантирована. Тарифы и бесплатные маршруты: [pricing](https://openrouter.ai/pricing/), [free router](https://openrouter.ai/docs/guides/routing/routers/free-router).

## Запуск монтажёра

Создание плана по реальному каталогу:

```bash
python3 planner_cli.py --task "Объясни результат и ограничения"
```

Исправление по замечаниям, относящимся к выбранному плану:

```bash
python3 planner_cli.py --task "Объясни результат и ограничения" --plan output/your-plan.json --review path/to/review.json
```

Результат сохраняется в JSON и ещё не считается принятым проверяющим. Каждая команда выводит путь созданного файла.

Проверка создания плана и доработки контрольного дефекта — два реальных API-запроса на учебном каталоге `examples/`:

```bash
python3 scripts/check_planner_live.py
```

[Сохранённые результаты](docs/evidence/planner/README.md) подтверждают работу монтажёра, а не всего мультимодального цикла.

## Полный запуск

```bash
python3 main.py --catalog data/catalog.json --task "Объясни результат и его ограничения"
```

Команда станет рабочей после подключения проверяющего. Сейчас она тратит один запрос на монтажёра и завершается статусом `failed`, потому что `review_plan` в live-режиме ещё не реализован. Без ключа запуск останавливается раньше, на монтажёре.

## Архитектура

| Модуль | Назначение |
|---|---|
| `planner.py` | Создание плана и исправление замечаний |
| `reviewer.py` | Проверка сцен по транскрипту и кадрам; сейчас только демонстрационный режим |
| `model_client.py` | Клиент OpenRouter: настройки, контроль бесплатных моделей, разбор JSON |
| `contracts.py`, `schemas/` | Проверки формы, ссылок, таймкодов, цитат и правил доработки |
| `main.py` | Порядок этапов, один раунд исправления, состояния и сохранение |
| `render.py` | Статическая HTML-раскадровка |

```text
main.py
  → build_plan(task, catalog)                  монтажёр, текстовая модель
  → validate_plan                              код
  → review_plan(task, catalog, plan, frames)   проверяющий, модель с изображениями
  → revise_plan(...) при замечаниях            монтажёр
  → validate_revision и повторная проверка     код и проверяющий
  → history.json, status.json, report.html     код
```

Без замечаний — два основных вызова модели, с одной доработкой — четыре. Если замечания остаются после повторной проверки, результат передаётся человеку.

Python и файлы работают локально, модели вызываются через API. Запуск Claude Code или Codex CLI внутри приложения, отдельная VM и база данных не требуются. Coding-агенты используются только для разработки.

## Данные и результаты

Каталог содержит исходную длительность, признак настоящих материалов и сегменты с `segment_id`, `start`, `end`, `transcript`, `frame_paths`. Пути кадров относительны файлу каталога и не выходят за его папку. План содержит ровно три сцены общей длительностью 20–30 секунд; проверка — одно решение на каждую сцену. Подробности — в [контрактах](docs/CONTRACTS.md).

При доработке сохраняются `scene_id` и принятые сцены. Полностью принятый план не вызывает дополнительный запрос, `needs_human_review` прекращает автоматическую доработку.

Каждый запуск сохраняется в отдельную папку `output/`: `input.json`, `plan_0.json`, `review_0.json`, при исправлении `plan_1.json` и `review_1.json`, затем `history.json`, `status.json` и `report.html`. Статусы: `demo_accepted`, `accepted`, `needs_human_review`, `failed`.

## Ограничения

Предобработка видео выполняется заранее. Экспорт MP4, музыка, озвучка и публикация не входят в текущую реализацию. По стоп-кадрам нельзя полностью оценить движение и звук; верность источнику не является независимым фактчекингом.

Секреты, `.env`, `output/`, виртуальное окружение и настройки IDE исключены из Git. Исходные видео в репозиторий не добавляются; материалы должны быть разрешены к передаче выбранному API-провайдеру. Существующий Java-шаблон IDEA к Python-MVP не относится.
