# ADR для CutCraft

Работай от корня репозитория. Прочитай `AGENTS.md`, `docs/adr/README.md` и относящиеся к задаче ADR; формат возьми из `docs/adr/TEMPLATE.md`. Перед описанием текущего поведения проверь код и документацию, связанные с решением.

## Когда нужен ADR

Фиксируй выбор, у которого есть разумные альтернативы и который меняет взаимодействие модулей, ограничения MVP, способ запуска, основной API-провайдер или бюджет. Конкретный model ID в пределах принятого бесплатного OpenRouter — обычно конфигурация, а не новое архитектурное решение.

Если меняется функция, prompt или исправляется баг без пересмотра выбора, достаточно обычного описания изменения. Не создавать ADR ради количества документов.

## Как оформить

- Следующий номер определить по реестру и файлам `docs/adr/`; не использовать занятый номер.
- Написать контекст и реальные альтернативы, затем выбранное решение, последствия и условия пересмотра. Обычно достаточно одной страницы.
- Различать факт реализации и выбор архитектуры. Статус «Принято» не доказывает, что код уже готов; не приписывать команде согласование, которого нет.
- Для нового, ещё не согласованного решения использовать «Предложено». Уже явно выбранное пользователем решение можно зафиксировать как принятое, обозначив область действия.
- При смене принятого решения создать новый ADR, старому поставить «Заменено ADR-NNNN» и добавить взаимные ссылки. Не переписывать историю мотивов под новый результат.
- Обновить реестр `docs/adr/README.md`; при изменении интерфейсов или запуска также обновить актуальные контракты/README, а не только ADR.

## Проверка

Проверить номера, ссылки, статусы и соответствие последствиям в коде. В альтернативы включать только содержательные варианты. Не включать личные советы участникам, требования оценивания, закрытые рабочие заметки или секреты.

Пример применения: перейти с одного раунда доработки на другой механизм остановки — проверить ADR-0001 и фактическую оркестрацию, описать причины и ограничения нового механизма. Само число раундов не менять без задачи.

Коммит, push и публикация ADR выполняются в рамках разрешения пользователя; skill сам такое разрешение не создаёт.
