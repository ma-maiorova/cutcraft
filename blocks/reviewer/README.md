## Проверка отдельно

После подключения модели и настройки окружения, из корня:

```python
import json
from pathlib import Path
from main import resolve_frames
from contracts import validate_review
from reviewer import review_plan
p = Path("data/catalog.json").resolve()
catalog = json.loads(p.read_text())
plan = json.load(open("examples/plan.json"))  # заменить подходящим планом для нового каталога
frames = resolve_frames(catalog, p.parent)
review = validate_review(review_plan("Объясни результат и ограничения", catalog, plan, frames), plan)
```

## Что учесть остальным

Сводка изменений из ветки `galim/reviewer` (поверх `main` после PR #1 и PR #2). Подробности: [ADR-0004](../../docs/adr/0004-multimodal-reviewer.md), [результаты](../../docs/evidence/reviewer/README.md).

**Всем**
- Формат review 1.0 не менялся. В [CONTRACTS.md](../../docs/CONTRACTS.md) добавлены требование к кадрам для живого критика и необязательный параметр `previous` у `review_plan`.
- Полный цикл `main.py` без `--demo` прошёл на реальном API дважды: монтажёр → проверки кодом → критик → `accepted` (2 запроса, 53–69 с, учебный каталог с PNG).
- Ветка доработки на двух живых моделях механически работает (замечание → правка → повторная проверка), но завершилась `needs_human_review` из-за повторного отказа критика по уже принятой сцене — исправлено переносом решений, live-повтор нужен.
- Тестов 38; все проходят вместе с `--demo`.

**Кирилл (общий клиент и оркестрация)**
- `model_client.py`, обратно совместимо: `chat_json(..., images=None, max_tokens=2200, reasoning=None, schema_name="cutcraft_plan")` — картинки как base64 `image_url` (только для модели с image input), лимит ответа, бюджет рассуждений.
- Общий лимит времени на ответ: раньше запрос мог висеть бесконечно — OpenRouter шлёт keepalive-байты, и socket timeout не срабатывал. Касается и монтажёра.
- Ошибки показывают причину от OpenRouter (например, «rate-limited upstream» против дневного лимита); при обрезке ответа — сколько токенов ушло на рассуждения (`ModelError.usage`, `.partial`).
- `main.py`: три строки — второй вызов `review_plan` получает `previous={"plan", "review"}` прошлого раунда.
- `render.py` не показывает поле `evidence` из review — полезно добавить в отчёт.

**Артём (данные)**
- Живой критик принимает только PNG/JPEG/WebP до 4 МБ, не больше 12 кадров на три сцены. Реальный каталог `data/` из PR #2 (JPEG, до 2 кадров на сегмент) этим требованиям соответствует — проверено кодом, live-прогон критика на нём ещё не делался.

**Марина (монтажёр)**
- В одном полном цикле монтажёр написал подписи по-английски при русском источнике. Стоит закрепить язык в `prompts/planner.txt`; критик теперь отмечает это как `revise_caption`.
- При одной доработке монтажёр изменил `source_quote`, и план отклонил контракт. Надёжнее восстанавливать исходный `source_quote` в коде при `revise_caption`. Отклонённый ответ модели сейчас не сохраняется — его не посмотреть.
- `dots-3-note-preview` — думающая модель: на критике она иногда тратит все 8000 токенов на рассуждения и не отвечает; бюджет `reasoning.max_tokens` игнорирует. Для монтажёра (короче вход, без картинок) это пока не проявлялось.
- В `blocks/planner/README.md` устарела фраза «live-цикл ждёт реализации reviewer.py».
