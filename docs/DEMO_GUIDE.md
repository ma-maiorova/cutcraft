# Демонстрация CutCraft

## Подготовка

Из корня репозитория:

```bash
python3 scripts/demo.py
```

Команда не вызывает API и не требует ключа. Она перестраивает два сохранённых реальных прогона текущим рендерером в новую папку output/presentation-… и печатает file-ссылки. Открыть обе заранее: saved-final.html — принятый план, saved-revision.html — исправление. На каждой странице есть пометка, что это ранее выполненный прогон. Подробного журнала старых запусков нет; отчёт честно восстанавливает этапы по файлам.

Для живого запуска настроить локальный .env по README и выполнить:

```bash
python3 scripts/demo.py --live
```

Сначала создаются резервные отчёты, затем проверяются каталог, наличие кадров и локальная конфигурация обеих моделей. Сетевая доступность и бесплатность модели проверяются существующим клиентом при вызове. Ключ не выводится. Основной цикл тратит 2–4 запроса; технические запросы каталога моделей считаются отдельно. Автоматических повторов и платного fallback нет.

При ошибке новый запуск не выдаётся за успешный, ссылки на сохранённые прогоны остаются в консоли. Если остались замечания, статус needs_human_review и код завершения 2; ошибка — 1, принятие или подготовка сохранённых отчётов — 0.

Проверка механики без моделей:

```bash
python3 scripts/demo.py --demo
```

Здесь ответы фиксированные. Замечание про симуляцию не соответствует теме текущего интервью; этот режим полезен для проверки программы, а качество ролей показываем на реальных прогонах.

## Когда показывать UI

Отчёт показываем после объяснения проблемы, входных данных и схемы ролей — ориентировочно на шестой минуте десятиминутного выступления. На терминал и UI выделяем 2–3 минуты. После демонстрации возвращаемся к результатам, ограничениям и дальнейшей оценке.

Один участник управляет экраном на протяжении всего показа. Рекомендуемый ведущий — Кирилл; остальные комментируют свои модули, не переключая демонстрацию между компьютерами.

## Порядок экранов

| Шаг | Экран и действие | Кто комментирует | Что показать |
|---|---|---|---|
| 1 | Терминал: `python3 scripts/demo.py --live` | Кирилл | начало нового запуска; резервные отчёты подготовлены до обращения к API |
| 2 | Новый `current/report.html`, если запуск завершился; иначе явно обозначенный `saved-final.html` | Кирилл | задание, режим и статус; не выдавать сохранённый прогон за свежий |
| 3 | Раздел «Шаги», раскрыть один `plan_0.json` | Кирилл, Марина | исполнители, входы/выходы и структура плана; не читать JSON целиком |
| 4 | «Итоговая раскадровка» | Артём | реальные кадры, выбранные фрагменты и исходные таймкоды |
| 5 | Открыть `saved-revision.html`, раздел «Решения проверяющего» | Галим | отклонённая сцена, evidence и requested_change из первой проверки |
| 6 | «Было → стало» | Марина | исправление заголовка по scene_id, сохранение принятых сцен |
| 7 | Повторная проверка и итог | Кирилл | принятие либо передача человеку; завершение ограниченного цикла |

Для поиска разделов использовать поиск браузера по указанным заголовкам. Не начинать показ с чтения большого JSON. Новое выполнение может пройти с первого раза: наличие исправления в каждом live-запуске не гарантируется, поэтому для этой ветки заранее открыт сохранённый пример.

Если API отвечает долго или завершился ошибкой, показать резервный отчёт и назвать его сохранённым реальным прогоном. Не запускать автоматическую серию повторов во время выступления. Новый `failed`-отчёт можно кратко показать отдельно, если есть время.

Старые реальные прогоны были записаны до появления events.json: в перестроенном UI шаги восстановлены по сохранённым артефактам, что обозначено на странице. Не приписывать им подробную телеметрию, которой не было.

## Проверка перед показом

- Открыть оба сохранённых отчёта и заранее найти нужные разделы.
- Проверить, что изображения отображаются и окна браузера/терминала удобно видны при демонстрации экрана.
- Проверить локальную конфигурацию до выступления; .env и панель ключей на экране не показывать.
- Живой запуск тратит квоту: для репетиции интерфейса использовать сохранённые отчёты.
- UI — статический отчёт после выполнения; кнопки запуска и live-прогресса в нём нет.
- Если подготовлено превью MP4, показать как дополнение после раскадровки; генерация видео не нужна в критическом пути демонстрации.

Описание проекта и архитектуры — в [PROJECT_PROPOSAL.md](PROJECT_PROPOSAL.md). Личные тексты выступления и подготовка к вопросам хранятся отдельно от репозитория.

## Тот же показ через Docker

После сборки образа по README можно подготовить отчёты и запустить цикл без локального Python:

```bash
mkdir -p output
docker build -t cutcraft:local .
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD/output:/app/output" cutcraft:local python scripts/demo.py
# Только после заполнения .env — новый реальный запуск:
docker run --rm --env-file .env --user "$(id -u):$(id -g)" -v "$PWD/output:/app/output" cutcraft:local python scripts/demo.py --live
```

Ссылки /app/output внутри контейнера соответствуют output на компьютере. Открывать HTML нужно из локальной папки. Интерфейс и порядок показа те же; контейнер — упаковка приложения, а не дополнительный агент.
