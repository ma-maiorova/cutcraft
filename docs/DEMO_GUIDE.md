# Демонстрация CutCraft

## Короткое описание проекта

CutCraft помогает собрать короткое объяснение из готового видео. Пользователь задаёт тему, монтажёр выбирает три фрагмента и пишет заголовки, а проверяющий сверяет их с транскриптом и кадрами. Если он находит искажение, монтажёр исправляет затронутые сцены. Код проверяет таймкоды и форматы и ограничивает цикл одной доработкой. На выходе — раскадровка, история решений и монтажный план; отдельный скрипт может собрать превью-видео.

Мы проверяем, помогает ли разделение создания и проверки находить ошибки при сокращении исходника. Работа цикла показана на одном интервью; улучшение качества на большой выборке пока не измеряли.

## Подготовка

Из корня репозитория:

```bash
python3 scripts/demo.py
```

Команда не вызывает API и не требует ключа. Она перестраивает два сохранённых реальных прогона текущим рендерером в новую папку output/presentation-… и печатает file-ссылки. Открыть обе заранее: saved-final.html — принятый план, saved-revision.html — исправление. На каждой странице есть пометка, что это ранее выполненный прогон. Подробного журнала старых запусков нет; отчёт честно восстанавливает этапы по файлам.

Для живого запуска настроить локальный .env по README и выполнить:

```bash
python3 scripts/demo.py --live
```

Сначала создаются резервные отчёты, затем проверяются каталог, наличие кадров и локальная конфигурация обеих моделей. Сетевая доступность и бесплатность модели проверяются существующим клиентом при вызове. Ключ не выводится. Основной цикл тратит 2–4 запроса; технические запросы каталога моделей считаются отдельно. Автоматических повторов и платного fallback нет.

При ошибке новый запуск не выдаётся за успешный, ссылки на сохранённые прогоны остаются в консоли. Если остались замечания, статус needs_human_review и код завершения 2; ошибка — 1, принятие или подготовка сохранённых отчётов — 0.

Проверка механики без моделей:

```bash
python3 scripts/demo.py --demo
```

Здесь ответы фиксированные. Замечание про симуляцию не соответствует теме текущего интервью; этот режим полезен для проверки программы, а качество ролей показываем на реальных прогонах.

## Сценарий показа на 2–3 минуты

**0:00–0:20 — задача и вход.** «Мы хотим короткий ролик про свидетельства Большого взрыва. На входе одно видео и задание. Транскрипт, сегменты и кадры подготовлены заранее — автоматическое распознавание не входит в показываемый агентный цикл». Показать data/catalog.json и один кадр.

**0:20–1:00 — новый запуск.** Запустить команду с --live. «Монтажёр получает текстовый каталог. Критик получает выбранные сцены, транскрипт и настоящие изображения; обоснование монтажёра ему скрыто. Оркестратор — код, он следит за форматом и числом попыток». Пока запрос идёт, показать схему из proposal. Наблюдавшиеся 22–34 секунды не гарантируют время нового ответа; при затяжном ожидании перейти к сохранённому отчёту, явно назвав его ранее выполненным.

**1:00–1:40 — результат и обмен.** Открыть новый report.html либо явно обозначенный сохранённый. Показать статус, шаги, раскрыть один plan JSON и перейти к раскадровке. «Здесь видно, что получил каждый участник и что вернул. Проверки кодом и решения моделей разделены».

**1:40–2:40 — исправление.** Открыть saved-revision.html. «Это сохранённый реальный прогон. Монтажёр добавил в заголовок факт из соседнего фрагмента. Критик указал несоответствие с цитатой. Монтажёр изменил только отклонённую сцену; принятые сохранились». Показать review_0, сравнение было/стало и повторное принятие. Не обещать, что новый запуск обязательно допустит такую же ошибку.

**2:40–3:00 — границы результата.** «Цикл работает, но это ещё не оценка надёжности. Обе роли используют одну модель, критик видит стоп-кадры, а не движение и звук. При повторном отказе решение остаётся человеку». Превью MP4 показывать только если оно уже подготовлено; оно не является отдельным агентом.

## Короткие ответы

- **Почему две роли?** Разные инструкции и контекст: первая создаёт, вторая проверяет по источнику. Пользу нужно отдельно измерить сравнением с вариантом без критика.
- **Почему оркестратор не LLM?** Очередность, ограничения и форматы известны; код обеспечивает воспроизводимое управление.
- **Что здесь агентное?** Решение критика управляет следующим действием: принять, исправить конкретные сцены или передать человеку. Это ограниченный цикл с обратной связью.
- **Что проверяют тесты?** Контракты, сохранение принятых сцен, работу цикла, передачу изображений и честное отображение ошибок. Они не доказывают качество суждений модели.
- **Что если API недоступен?** Показываем явно подписанный сохранённый реальный прогон и объясняем ошибку нового запуска.
