# Демонстрация CutCraft

На выходе запуска две вещи, обе в одной папке `output/<timestamp>/`:

- `report.html` — план ролика: задание, шаги, решения проверяющего, «было → стало» и итоговая раскадровка;
- `short.mp4` — готовое вертикальное видео по этому плану.

## Подготовка

Ключ в `.env`, нужное видео в папке `media/`, затем:

```bash
docker compose build
```

## Запуск на защите

```bash
docker compose -f compose.yaml -f compose.live.yaml run --rm app
```

Проверка входа и настроек, цикл (2–4 запроса к API), сборка видео.

Коды завершения: `accepted` — 0, `needs_human_review` — 2, ошибка — 1.

## Когда показывать

Отчёт показываем после объяснения проблемы, входных данных и схемы ролей, примерно на шестой минуте. На терминал, отчёт и видео выделяем 2–3 минуты. Один участник управляет экраном, остальные комментируют свои модули.

| Шаг | Экран | Кто комментирует | Что показать |
|---|---|---|---|
| 1 | Терминал: команда запуска | Кирилл | вход проверен, идут запросы к моделям |
| 2 | `report.html`, шапка и «Шаги» | Кирилл, Марина | задание, статус, кто что получил и вернул |
| 3 | «Решения проверяющего» | Галим | решение по каждой сцене со свидетельством |
| 4 | «Было → стало», если было исправление | Марина | какая сцена исправлена и как |
| 5 | «Итоговая раскадровка» | Артём | кадры, таймкоды, заголовки, цитаты |
| 6 | `short.mp4` | Артём | готовый ролик по плану, 20–30 секунд |

Новый запуск может пройти без исправления: проверяющий часто принимает план сразу. Чтобы гарантированно показать исправление, используйте режим с контрольной ошибкой (ниже).

## Проверка перед показом

- Docker запущен, образ собран, есть интернет.
- `.env` на экране не показывать.

Описание проекта и архитектуры — в [PROJECT_PROPOSAL.md](PROJECT_PROPOSAL.md).

## Запуск с контрольной ошибкой

Чтобы показать, как проверяющий ловит неверную подпись:

```bash
docker compose -f compose.yaml -f compose.live.yaml run --rm app python scripts/demo.py --live --controlled-defect
```

Монтажёр сначала создаёт настоящий план через API, оригинал сохраняется как `plan_generated.json`. Затем код заменяет первую подпись на «Большой взрыв произошёл вчера в Москве» и записывает это в `controlled_defect.json`. Проверяющий, доработка и повторная проверка идут через реальные API, решения заранее не заданы. Видео собирается по итоговому, исправленному плану.

В `report.html` и журнале вмешательство помечено. Это тест способности проверяющего найти внесённую ошибку, а не естественный дефект монтажёра. Если проверяющий принял испорченную сцену, скрипт так и пишет и завершается кодом 3.
