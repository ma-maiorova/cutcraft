# CutCraft — project proposal

Команда 28 · защита 16 октября 2026

## 1. Идея

CutCraft помогает сделать короткий ролик из длинного видео. Пользователь пишет, о чём должен быть ролик, а система выбирает три подходящих фрагмента, ставит их в порядок рассказа и пишет к каждому короткий заголовок. Отдельный агент проверяет результат по исходнику и кадрам и возвращает неудачные сцены на исправление.

## 2. Пользователь и проблема

Проект рассчитан на авторов научно-популярных, образовательных и новостных нарезок из интервью и лекций. Найти в длинном видео моменты под конкретную тему и связать их в сюжет — долгая ручная работа.

При сокращении легко исказить смысл, хотя каждое слово в ролике настоящее. Фраза «метод работает, но пока только на симуляции» превращается в заголовок «метод доказан», а в кадр попадает заставка вместо обсуждаемого графика. В наших прогонах монтажёр-LLM делал похожее: приписывал фрагменту вывод из соседнего куска интервью. Проверяющий это ловил.

Экономию времени на реальных пользователях мы не измеряли, это гипотеза.

## 3. Почему LLM и агенты

Выбрать фрагменты под задание можно только по смыслу речи: поиск по словам не отличит тезис от оговорки. Соответствие кадра подписи оценивает модель, которая видит изображения.

Одного вызова модели мало. Монтажёр не видит кадры и иногда добавляет в заголовок то, чего в выбранном фрагменте нет. Проверяющий получает транскрипт, кадры и неиспользованные фрагменты, но не видит объяснений монтажёра, и проверяет план по источнику. Если он находит ошибку, монтажёр исправляет только затронутую сцену.

## 4. MVP

**Вход:** текстовое задание и каталог одного видео. В демо это интервью Бориса Штерна о подтверждениях Большого взрыва: 15 фрагментов, покрывающих всю речь спикера, с транскриптом, таймкодами и настоящими кадрами ([источник](../data/SOURCE.md)). Транскрипт сделан заранее через Whisper. Вручную сверены восемь фрагментов; семь добавленных фрагментов ещё требуют прослушивания. Точный список и исправления указаны в описании источника.

**Выход:** план из трёх сцен общей длительностью 20–30 секунд. У каждой сцены есть таймкоды, короткий заголовок и дословная цитата. Оркестратор сохраняет версии плана и замечаний, журнал событий и строит HTML-отчёт: шаги, исполнители, входы и выходы, решения проверяющего, сравнение «было → стало» и итоговая раскадровка.

Заголовок сцены — это крупный текст на экране, 4–8 слов. Дословные субтитры берутся из транскрипта и модель их не пишет.

По готовому плану отдельный скрипт собирает вертикальное видео 9:16 с заголовками и субтитрами. Модели в нём не участвуют. Это превью будущего экспорта, а не часть агентного цикла.

В MVP не входят поиск видео, загрузка на YouTube, озвучка, музыка, переходы, несколько исходников и анализ звука и движения.

## 5. Архитектура

```text
задание + каталог
      ↓
монтажёр (LLM): 3 сцены, тезис → доказательство → вывод
      ↓
код: сегменты существуют, 20–30 с, цитаты дословные
      ↓
проверяющий (LLM с изображениями): текст + кадры
      ├── всё принято → accepted
      └── замечания → монтажёр исправляет затронутые сцены → код → повторная проверка
                                                         ├── принято → accepted
                                                         └── иначе → needs_human_review
```

Оркестратор написан обычным кодом. Порядок шагов, форматы, таймкоды и лимиты известны заранее, и код контролирует их надёжнее модели. Цикл ограничен одним исправлением: в наших прогонах этого хватало, а если нет, решение остаётся за человеком.

Модели вызываются через OpenRouter, только бесплатные варианты `:free`. В текущем шаблоне настроек для обеих ролей выбрана `nvidia/nemotron-3.5-super-vl:free`; сохранённые успешные прогоны на реальном видео получены с ней. Это не сравнительная оценка стабильности моделей. Модель задаётся в `.env`, код от неё не зависит.

## 6. Контракты

| Контракт | Что внутри |
|---|---|
| [Каталог](../schemas/catalog.schema.json) | фрагменты, таймкоды, транскрипт, пути кадров |
| [План](../schemas/plan.schema.json) | три сцены, заголовки, цитаты, обоснование выбора |
| [Проверка](../schemas/review.schema.json) | решение по каждой сцене, замечание, свидетельство, правка |

JSON Schema задаёт форму. `contracts.py` проверяет связи между файлами: существование сегментов, границы, длительность, точное вхождение цитаты в транскрипт, сохранение принятых сцен при исправлении. Техническая проверка не доказывает смысловую точность, это задача проверяющего. Подробнее — в [CONTRACTS.md](CONTRACTS.md).

## 7. Демонстрация

[Команды запуска и сценарий рассказа](DEMO_GUIDE.md): подготовка сохранённых отчётов без API и новый запуск с резервным вариантом.

```bash
python3 main.py --catalog data/catalog.json --task "Объясни за 30 секунд, почему учёные уверены, что был Большой взрыв"
python3 scripts/render_short.py --video shtern_big_bang.mp4
```

В двух сохранённых успешных прогонах цикл занял 21,62 секунды без доработки и 34,08 секунды с одной доработкой. Это наблюдения отдельных запусков, а не гарантия времени ответа API. Задание нужно подбирать под содержание видео: в этом интервью нет разговора об ограничениях метода, и с заданием «объясни результат и ограничения» монтажёр притягивал случайный фрагмент.

На защите показываем два сохранённых прогона ([результаты](evidence/real_video/README.md)):

- итоговый: тезис «масса свидетельств о Большом взрыве» → разбегание галактик (на кадре схема красного смещения) → вывод. Проверяющий принял план сразу;
- пример исправления: монтажёр приписал сцене слова «после открытия реликтового излучения», которых в этом фрагменте нет. Проверяющий вернул сцену с цитатой источника, монтажёр исправил только её, повторная проверка прошла.

### Интерфейс истории

Страница истории реализована Кириллом и включена в main ([описание](RUN_HISTORY_UI.md)). После запуска открывается локальный `report.html`: сверху задание, режим и статус; затем шаги с исполнителями и раскрываемыми JSON, решения критика с evidence, сравнение версий по scene_id и итоговые кадры. Сбой сохраняет доступную часть истории. Старые запуски без events.json отображаются с пометкой об отсутствии подробного журнала.

Это статический отчёт после выполнения: кнопки запуска и обновления прогресса в реальном времени нет. Просмотр не вызывает модели. Для открытия достаточно браузера, сервер не требуется.

Проверить интерфейс без API:

```bash
python3 main.py --demo
```

Демо использует фиксированные ответы на настоящем каталоге. Его контрольное замечание про симуляцию не соответствует теме интервью и служит только демонстрацией ветвления; качество моделей показываем на сохранённых реальных прогонах. Перестроить такой отчёт текущим рендерером можно без API:

```bash
python3 render.py docs/evidence/real_video/revision --out output/revision-report.html
```

## 8. Что проверено

| Проверка | Результат на 16 октября |
|---|---|
| Автоматические тесты | 54 проходят, включая демо, журнал, отчёт после ошибки, сравнение сцен по ID и экранирование текста |
| Монтажёр на учебном каталоге | план и одна контрольная правка, [результаты](evidence/planner/README.md) |
| Проверяющий на контрольных случаях | 3 из 3 на синтетических PNG с Dots; на текущей Nemotron набор ещё не повторён, [результаты](evidence/reviewer/README.md) |
| UI истории | После демо проверены отображение этапов, раскрытие JSON, решения критика и сравнение версий; обработка неполной истории покрыта тестами |
| Полный цикл на реальном видео | `accepted`, связный сюжет; в другом прогоне найдено и исправлено искажение, [результаты](evidence/real_video/README.md) |

Это единичные прогоны, а не оценка надёжности. Бесплатные модели бывают недоступны (429) или тратят весь лимит токенов на рассуждения. Ответ модели меняется от запуска к запуску. Проверяющий видит стоп-кадры и не слышит звук. Обе роли сейчас работают на одной модели, поэтому независимость проверки ограничена: у ролей разные инструкции и данные, но ошибки модели могут совпадать. Верность источнику не означает проверку фактов в мире.
