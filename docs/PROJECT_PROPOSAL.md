# CutCraft — project proposal

Команда 28 · 16 октября 2026

## 1. Идея проекта

CutCraft — помощник подготовки коротких эдитов из готового видео. Система выбирает фрагменты под задание пользователя и формирует монтажный план с таймкодами, стоп-кадрами и подписями.

Целевая архитектура включает две роли: монтажёр составляет план, а проверяющий сопоставляет его с исходным материалом и возвращает конкретные замечания. Монтажёр исправляет отклонённые сцены; число итераций ограничено.

## 2. Пользователь и проблема

Проект предназначен для авторов коротких роликов из интервью, объяснений и обзоров. Подготовка такого ролика требует выбрать подходящие моменты, связать их в последовательность и написать подписи, сохранив смысл источника.

При сокращении легко потерять существенное ограничение. Например, фраза «метод пока проверили только на симуляции» может превратиться в неподтверждённое «метод доказал эффективность».

CutCraft помогает подготовить черновик монтажа с явными ссылками на источник и историей исправлений. Экономия времени и полезность для пользователей пока рассматриваются как гипотезы для последующей оценки.

## 3. Границы MVP

**Вход:** задание пользователя и подготовленный каталог 6–8 фрагментов одного видео. Каждый фрагмент содержит таймкоды, транскрипт и стоп-кадры.

**Результат:** три сцены общей длительностью 20–30 секунд, подписи, цитаты из источника и машиночитаемый монтажный план. Демонстрационный каркас также формирует HTML-раскадровку с историей версий.

Транскрипт, сегментация и извлечение кадров выполняются заранее. Экспорт MP4, музыка, озвучка, сложные переходы и публикация находятся за границами текущего MVP.

## 4. Архитектура и оркестрация

```text
Задание + каталог
        ↓
Монтажёр-планировщик
        ↓
Техническая валидация
        ↓
Проверяющий-критик
        ├── принято → результат
        └── замечания → исправление → повторная проверка
```

**Монтажёр-планировщик** выбирает фрагменты, их порядок и подписи. При доработке он получает текущий план и замечания, меняет затронутые сцены и сохраняет принятые.

**Проверяющий-критик** предназначен для проверки верности пересказа, соответствия кадров и подписей, а также связности плана. Для каждой сцены контракт предусматривает решение, свидетельство и запрашиваемое изменение.

**Оркестратор** — обычный код: он управляет этапами, проверяет данные и сохраняет состояние. Предусмотрены один раунд исправления и повторная проверка; нерешённые замечания передаются человеку.

LLM используется для смыслового отбора и редактирования. Агентный цикл позволяет менять план по результату проверки. Фиксированные правила — таймкоды, формат и лимиты — контролируются кодом.

Приложение работает локально и обращается к моделям через API OpenRouter. Текстовый монтажёр проверен на бесплатной модели `dots-studio/dots-3-note-preview:free`. Подключение мультимодального критика является следующим этапом интеграции.

## 5. Контракты и контроль результата

| Контракт | Содержание |
|---|---|
| [Каталог](../schemas/catalog.schema.json) | Сегменты, исходные таймкоды, транскрипт и пути кадров |
| [План](../schemas/plan.schema.json) | Три сцены, подписи, цитаты и основания выбора |
| [Проверка](../schemas/review.schema.json) | Решение и замечания для каждой сцены |

JSON Schema задаёт форму ответа. Код дополнительно проверяет существование сегментов, уникальность идентификаторов, допустимые границы, общую длительность и наличие цитаты в транскрипте.

При исправлении сохраняются идентификаторы сцен и содержимое принятых сцен. Если весь план принят, дополнительный запрос к модели не выполняется. Решение `needs_human_review` прекращает автоматическую доработку.

Техническая валидность не гарантирует смысловую точность. Сопоставление содержания и визуального материала требует отдельной проверки.

## 6. Демонстрационный сценарий

Демонстрация модуля монтажёра показывает создание плана и его изменение по конкретному замечанию:

1. Передать модели задание и каталог фрагментов.
2. Получить и технически проверить план из трёх сцен.
3. Внести контрольную неподтверждённую подпись и передать подготовленное замечание.
4. Получить исправленный план и проверить сохранение принятых сцен.

[Сохранённые результаты](evidence/planner/README.md) получены двумя реальными API-запросами на учебном каталоге. Контрольное замечание подготовлено заранее и не является результатом агента-критика.

```bash
# Настоящий монтажёр: создание плана
python3 planner_cli.py --task "Объясни результат и ограничения"

# Создание и исправление контрольного дефекта: два API-запроса
python3 scripts/check_planner_live.py

# Демонстрационный каркас без API, с фиксированными ответами
python3 main.py --demo
```

Полный сценарий проекта дополнит эту последовательность реальными данными и замечаниями мультимодального критика.

## 7. Результаты и ограничения

| Проверка | Результат на 15 октября |
|---|---|
| Автоматические тесты | 22 теста прошли |
| Реальное создание плана | Успешно на учебном каталоге |
| Реальное исправление подписи | Успешно по подготовленному замечанию |
| Сохранение принятых сцен | Подтверждено в контрольном запуске |
| Демонстрационный каркас и HTML | Работают с фиксированными ответами |
| Полный цикл на настоящем видео с критиком | Ещё не подтверждён |

Бесплатные модели могут ограничивать запросы: при проверке встречались ответы HTTP 429. Платного переключения и бесконечных повторов в клиенте нет.

Текущий успешный пример использует синтетический транскрипт и условные изображения. Он подтверждает работу модуля монтажёра и контроля доработки, но не качество анализа настоящего видео. Стоп-кадры не позволяют полностью оценить движение и звук, а верность источнику не равна независимому фактчекингу.

Дальнейшая оценка включает длительность запуска, число запросов, обнаружение известных дефектов, пропуски и ложные замечания. Базовый вариант для сравнения — план первого прохода без критики.
