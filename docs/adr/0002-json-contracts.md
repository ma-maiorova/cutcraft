# ADR-0002: JSON Schema и межфайловая валидация

Дата: 2026-10-15  
Статус: Принято для MVP  
Связь: [контракты](../CONTRACTS.md), [схемы](../../schemas/), [PR #1](https://github.com/cemouse/cutcraft/pull/1)

## Контекст

Четыре участника независимо готовят данные, монтажёра, проверяющего и оркестратор. Без общего формата их модули будут требовать ручной адаптации. Структурированный ответ модели сам по себе не гарантирует корректность ссылок и таймкодов.

Альтернативы: свободный текст между ролями; отдельные несогласованные форматы; только проверка JSON Schema без связей между данными.

## Решение

Использовать версию 1.0 для трёх объектов: catalog, plan и review. Схемы Draft 2020-12 лежат в schemas/, эталонные примеры — в examples/. Неизвестные поля в версии 1.0 отклоняются. Расширения формата согласуются между владельцами модулей.

contracts.py проверяет дополнительные условия: уникальность ID, существование сегмента, границы, общую длительность, точное вхождение цитаты и полноту review. validate_revision сохраняет идентификаторы и принятые сцены. Модель при поддержке получает строгий structured output, но её ответ всё равно валидируется кодом.

## Последствия

Модули можно разрабатывать на общих примерах; технические ошибки обнаруживаются до следующего этапа. Строгий формат требует согласованно менять схемы, валидаторы, примеры и инструкции. Отдельная JSON Schema не выражает все межфайловые условия; техническая проверка не заменяет смысловую или визуальную.

## Пересмотр

При изменении совместимости форматов зафиксировать миграцию и версию. Ввод другого способа обмена между ролями оформить новым ADR.
