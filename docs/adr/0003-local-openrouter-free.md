# ADR-0003: локальный запуск и бесплатный OpenRouter

Дата: 2026-10-15  
Статус: Принято для MVP  
Связь: [настройки](../../.env.example), [клиент](../../model_client.py), [результаты](../evidence/planner/README.md)

## Контекст

Для MVP нужен доступ к текстовой модели, а для критика — к модели с изображениями. Бюджет текущего этапа ограничен бесплатными запросами. Собственный сервер моделей и отдельная VM добавляют настройку, которая не нужна для локальной демонстрации.

Альтернативы: прямой API другого провайдера; собственная локальная LLM; запуск coding-agent CLI внутри приложения; облачный сервер приложения.

## Решение

Запускать Python-приложение и хранить результаты локально, обращаться к моделям через официальный API OpenRouter. Выбирать точные ID вариантов :free и перед запросом подтверждать нулевые цены по каталогу. Платный fallback исключён.

Ключ хранится в локальном .env или окружении, в Git — только .env.example. Клиент ограничивает время запросов и возвращает понятную ошибку; бесконечных повторов нет. Claude Code/Codex могут помогать разработке, но не являются обязательным runtime приложения.

Конкретный бесплатный model ID — конфигурация. Успешно проверена dots-studio/dots-3-note-preview:free для текста; модель критика должна отдельно пройти проверку реальными изображениями.

## Последствия

Не нужны собственная GPU и VM; провайдера используют оба модуля. Требуются интернет, ключ и доступная квота. Бесплатные модели могут отвечать 429 или меняться в каталоге. Сохранённые результаты позволяют изучить запуск при недоступности API, но не подменяют новый live-запрос.

## Пересмотр

Переход на платные модели, другой провайдер как основной, самостоятельный inference или обязательное удалённое развёртывание оформить отдельным решением с бюджетом и условиями обработки данных.
